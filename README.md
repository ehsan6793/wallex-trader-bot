# ربات معامله‌گر الگوریتمی والکس (هکاتون استارکوچ)

موتور معاملاتی خودکار برای بازارهای **تومانی** والکس. هستهٔ تصمیم یک **مدل یادگیری ماشین** است که هر چند ساعت دوباره آموزش می‌بیند. یک **لایهٔ قوانین ریسک** هم دارد که قطعی (deterministic) است. ناظر **LLM** اختیاری است و فقط می‌تواند ریسک را کم کند. بک‌تست، شادو تست و اجرای زنده هر سه **دقیقاً از همین کد** استفاده می‌کنند.

## اجرا

```bash
pip install -r requirements.txt
cp .env.example .env              # کلید API و زمان پایان چالش را وارد کنید
python -m bot check               # تست اتصال، بازارها، موجودی و کارمزد واقعی (سفارشی ثبت نمی‌شود)
python -m bot backtest --days 7   # بک‌تست walk-forward روی دادهٔ واقعی ۷ روز اخیر → reports/
python -m bot dashboard           # داشبورد گرافیکی
python -m bot shadow              # شادو تست: قیمت و دفتر سفارش زنده، سفارش‌ها شبیه‌سازی می‌شوند
python -m bot live --yes          # اجرای واقعی
python -m bot report --mode live  # خلاصهٔ عملکرد از روی لاگ‌ها
python -m bot flatten --yes       # فروش اضطراری همهٔ دارایی‌ها به تومان
python -m pytest -q               # ۱۱ تست آفلاین (بدون اینترنت)
```

برای اجرای مجدد توسط داوران: یک کلید API والکس در `.env` بگذارید. `backtest` و `shadow` با هر حسابی قابل اجرا هستند و پولی جابه‌جا نمی‌کنند. `backtest` حتی بدون کلید هم کار می‌کند.

## معامله‌ی نمایشی ۱ دقیقه‌ای (`python -m bot demo`)
یک دور کامل خرید و فروش واقعی روی **کندل ۱ دقیقه‌ای** برای اثبات کل زنجیرهٔ اجرا (سیگنال ← سفارش LIMIT ← پر شدن ← خروج ← تومان). بدون هیچ ورودی دستی؛ همه‌چیز الگوریتمی و لاگ‌شده است. زیان ناشی از کارمزد و اسپرد مورد انتظار است.

- **ورود:** افت ≥ ۰٫۲۵٪ در ۱۵ کندل ۱ دقیقه‌ای و کندل آخر سبز و اسپرد کم؛ بازاری که بیشترین افت را دارد انتخاب می‌شود.
- **ورود اجباری شفاف:** اگر در `DEMO_WAIT_MIN` دقیقه (پیش‌فرض ۵) سیگنال طبیعی نیامد، بازار با کمترین اسپرد خریده می‌شود و دلیل در لاگ دقیقاً با عنوان «ورود نمایشی اجباری (forced demo entry)» ثبت می‌شود.
- **خروج:** حد سود ۰٫۳۵٪، حد ضرر ۰٫۵٪ یا ۲۴۰ ثانیه؛ هر کدام زودتر برسد.
- **ایمنی:** فقط یک دور معامله، مبلغ ثابت `DEMO_AMOUNT` (پیش‌فرض ۵۰۰٬۰۰۰ تومان)، فقط همان کوینی که خود این اجرا خریده فروخته می‌شود، شروع نمی‌کند اگر کمتر از ۲۵ دقیقه به پایان چالش مانده باشد، و اگر ۳۰ دقیقه خریدی انجام نشد متوقف می‌شود.
- **لاگ جدا:** `logs/trades_demo.csv`، `logs/decisions_demo.jsonl`، `logs/events_demo.log`.
- **اجرا:** `python -m bot demo` (شبیه‌سازی روی قیمت زنده) و `python -m bot demo --yes` (واقعی)؛ یا `5_demo_shadow.bat` و `5_demo_live.bat`.

## معماری

```
api.py        کلاینت REST والکس (X-API-Key، retry، رعایت دقت قیمت/مقدار)
data.py       دریافت کندل ۵ دقیقه‌ای از /v1/udf/history + کش
features.py   ۱۷ ویژگی (بازده چندبازه‌ای، RSI، فاصله از EMA، شیب روند، ATR، حجم، بولینگر…) + برچسب triple-barrier
model.py      رگرسیون لجستیک (numpy، قطعی) + انتخاب آستانه روی دادهٔ اعتبارسنجی خارج از نمونه
strategy.py   قوانین ورود/خروج، اندازهٔ پوزیشن، توضیح هر تصمیم
broker.py     PaperBroker (شادو) و LiveBroker (سفارش LIMIT با سقف قیمت، پیگیری، لغو باقیمانده)
llm.py        ناظر ریسک LLM (وتو/کاهش ریسک؛ هرگز افزایش ریسک)
engine.py     حلقهٔ زنده: قیمت → خروج‌ها → آموزش دوره‌ای → سیگنال روی هر کندل بسته‌شده → ورود
backtest.py   بک‌تست رویدادمحور walk-forward با همان strategy/model
journal.py    لاگ تصمیم (JSONL)، معاملات و منحنی سرمایه (CSV)، state
```

### قواعد نهایی
- **بازارها:** ۸ بازار اصلی تومانی: BTC، ETH، BNB، SOL، XRP، DOGE، TRX، XAUT.
- **ورود:** قیمت در ۲ ساعت اخیر (۸ کندل ۱۵ دقیقه‌ای) ۳٪ یا بیشتر افت کرده باشد. اسپرد کم باشد، روی همان نماد پوزیشن باز نباشد، حد افت سرمایه رد نشده باشد، LLM وتو نکرده باشد و اپراتور ورودها را متوقف نکرده باشد.
- **حجم:** ریسک ۰٫۸٪ سرمایه تا حد ضرر، با سقف ۳۰٪ برای هر پوزیشن. **مدل ML** این حجم را بر اساس احتمال موفقیت در ضریب ۰٫۷ تا ۱٫۳ ضرب می‌کند.
- **خروج:** اولین اتفاق از این‌ها: حد سود ۳٪+، حد ضرر ۴٪−، یا ۸ ساعت نگهداری. بعد از ۲٪ سود، حد ضرر به نقطهٔ سربه‌سر منتقل می‌شود.
- **پایان چالش:** ۹۰ دقیقه مانده به پایان، ورود جدید متوقف می‌شود. ۲۰ دقیقه مانده به پایان، همه‌چیز به تومان فروخته می‌شود.

### بک‌تست کامل ربات (walk-forward، ۱۴ روز تا ۲۲ اکتبر، شامل سقوط ۸ اکتبر)

| شاخص | مقدار |
|---|---|
| بازده | ۱٫۸٪+ |
| حداکثر افت سرمایه | ۱٫۸٪ |
| تعداد معامله | ۱۲ |
| نرخ برد | ۷۵٪ |
| Profit factor | ۷٫۳ |
| خرید و نگهداری در همین دوره | ۳٫۶٪− |

هر دو هفته مثبت بود. ربات بیشتر وقت‌ها نقد است. **سود تضمینی نیست:** در بازار بدون افت تند، ربات معامله‌ای نمی‌کند.

بازتولید: `python -m bot backtest --csv-dir data_snapshot --days 14`

## تایم‌فریم‌ها و ناظر LLM
- **تایم‌فریم‌ها:** هر ۱۵ دقیقه برای هر بازار وضعیت روند و RSI روی ۱ دقیقه، ۵ دقیقه، ۱۵ دقیقه، ۳۰ دقیقه، ۱ ساعت و ۴ ساعت محاسبه می‌شود (`bot/mtf.py`).
- **چرا فقط ۱۵ دقیقه معامله می‌کند:** طبق `research/run4.py`، همان قاعده روی تایم‌فریم‌های دیگر ضعیف‌تر یا زیان‌ده بود و فیلترهای تایم‌فریم بالاتر نتیجه را بهتر نکردند. برای همین تایم‌فریم‌های دیگر فقط **زمینه** هستند: در داشبورد نمایش داده می‌شوند و به ناظر LLM داده می‌شوند.
- **صرفه‌جویی در توکن LLM:**
  - LLM فقط وقتی فراخوانی می‌شود که قاعده سیگنال خرید بدهد. در غیر این صورت، فقط هر ۳ ساعت یک بار و تنها وقتی پوزیشن باز وجود دارد.
  - ورودی فشرده است، پاسخ حداکثر ۱۲۰ توکن است و سقف روزانه ۳۰ فراخوانی است (`LLM_MAX_CALLS_PER_DAY`).
  - مصرف توکن در لاگ و داشبورد ثبت می‌شود.
  - هر خطای LLM یعنی «بدون وتو»؛ یعنی LLM هیچ‌وقت معامله‌ای را مجبور یا قفل نمی‌کند.

## داشبورد
`python -m bot dashboard` یا `4_dashboard.bat` داشبورد را در آدرس http://127.0.0.1:8765 باز می‌کند. `3_live.bat` و `2_shadow.bat` هم آن را خودکار باز می‌کنند. داشبورد این‌ها را نشان می‌دهد:
- ارزش حساب، سود و زیان، بازده، حداکثر افت سرمایه، نرخ برد و حجم معاملات
- منحنی سرمایه
- نمودار قیمت هر بازار با علامت خرید و فروش
- پوزیشن‌های باز
- آخرین سیگنال و احتمال ML هر بازار
- اعلان‌ها و نظر ناظر LLM
- جدول معاملات با دلیل هر معامله
- شمارش معکوس تا پایان چالش

**کنترل‌های ایمنی:** توقف ورودهای جدید، ادامه، و فروش اضطراری همه‌چیز به تومان.

**حالت تأیید انسانی** (`APPROVAL_MODE=1`): هر سیگنال قبل از اجرا با دکمهٔ «تأیید/رد» در داشبورد تأیید می‌شود. این حالت **برای حساب چالش مجاز نیست**، چون قانون چالش معاملهٔ دستی را ممنوع کرده است.

### نقش هوش مصنوعی

1. **مدل ML (رگرسیون لجستیک، numpy، قطعی):**
   - **آموزش:** روی ۱۴ روز اخیرِ همهٔ نمادها و هر ۶ ساعت دوباره (walk-forward).
   - **برچسب triple-barrier:** همان حد سود، حد ضرر و افق زمانیِ معاملهٔ واقعی.
   - **نقش‌ها:** فیلتر ورود، تعیین حجم، و زمان‌بندی خروج.
   - **توضیح‌پذیری:** سهم ویژگی‌های اثرگذار برای هر تصمیم لاگ می‌شود.
2. **ناظر LLM (Agentic):**
   - هر ۳۰ دقیقه تصویر خلاصه‌ای از بازار، سیگنال‌ها، اسپرد و افت سرمایه را بررسی می‌کند.
   - فقط می‌تواند نمادی را وتو کند یا ریسک را کم کند (ضریب ۰٫۳ تا ۱).
   - پاسخ‌هایش لاگ می‌شوند.

## مدیریت سرمایه و ریسک

- **ریسک هر معامله:** اگر حد ضرر بخورد، حداکثر ۰٫۸٪ سرمایه از دست می‌رود.
- **سقف هر پوزیشن:** ۳۰٪ سرمایه.
- **حداکثر پوزیشن هم‌زمان:** ۳.
- **نقدینگی:** همیشه ≥۱۰٪ نقد باقی می‌ماند.
- **افت ۴٪:** ورود جدید متوقف می‌شود.
- **افت ۶٪:** همهٔ پوزیشن‌ها بسته می‌شوند و ربات متوقف می‌شود.
- **سفارش‌ها:** فقط LIMIT با سقف قیمت ثبت می‌شوند (بدون Market بی‌سقف). باقیماندهٔ پرنشده لغو می‌شود. دقت مقدار، `minNotional` و `minQty` بازار رعایت می‌شود.
- **کارمزد:** نرخ واقعی کارمزد حساب از `/v1/account/fee` خوانده و در همهٔ محاسبات لحاظ می‌شود.
- **بعد از ری‌استارت:** پوزیشن‌ها از state بازیابی می‌شوند. کوین‌های موجود در کیف پول هم مدیریت می‌شوند.

## محدودیت‌ها

- سود تضمین‌شده نیست. در بازار نزولی ربات عمدتاً نقد می‌ماند.
